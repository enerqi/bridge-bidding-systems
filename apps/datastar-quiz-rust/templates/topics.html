{#- The topics picker. A native , opened by a local signal rather than a server round trip -- "toggling element visibility" is exactly what the Tao of Datastar says signals are for, and the server has no interest in whether a panel is open. Ticking boxes changes `$topics` (no underscore, so it is uploaded) but commits nothing: the working set only changes on Apply. Escape closes it, and closing DISCARDS -- same path as the Close button. A NON-modal dialog (`open`, not `showModal()`) gets no Escape handling from the browser, so it is wired by hand; the guard on `$_topicsOpen` keeps the key free for anything else when the picker is shut. -#}

Topics

Pick any number — an auction matching any selected topic is included. Nothing changes until you press Apply, which replaces whatever is in the filter box.

{#- Everything that can grow is inside ONE scroller, and the buttons are outside it. The whole card used to scroll, so with nineteen topics Apply / Clear / Close were sliced in half at the bottom edge -- the actions of a dialog should never be the thing you have to scroll to find. The list itself flows into as many columns as the card is wide enough for. -#}

{#- `@setAll(false, {include: /^topics\./})`, NOT `$topics = {}`. The boxes are bound one signal at a time (`data-bind:topics.`), so `topics` is a NAMESPACE, not a value: assigning an empty object to it replaces the branch the bindings are watching instead of writing to the leaves, and every box stayed ticked. `@setAll` walks the signal tree and writes each matching leaf. The `@get` after it is not decoration: the status line under the list is server-rendered from the ticks, so without it Clear leaves "N topics selected" under an empty list. -#} {#- Close is CANCEL: it discards the ticks and puts them back to the filter in force. The dialog's first line promises that nothing changes until Apply, and keeping an abandoned draft is the one way to break that promise without touching the filter. -#}
